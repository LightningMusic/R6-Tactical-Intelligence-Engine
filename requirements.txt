# USB CLIENT dependencies only. This file (and the :env_setup step inside
# build_and_deploy.bat, which is the actual source of truth for the build
# venv — it installs its own explicit package list rather than `pip
# install -r requirements.txt`, so a package added here must also be added
# there) must never gain a server-only package (fastapi, uvicorn,
# python-multipart, ...) — those live in server/requirements.txt instead.
# The client is packaged as a single isolated .exe via
# R6Analyzer.spec/PyInstaller, so every package listed here gets bundled
# onto the USB stick; keep this list to what the desktop app itself
# actually imports.
#
# (resemblyzer/scikit-learn below went missing from build_and_deploy.bat's
# install list for a while after being added here — nothing caught the
# drift because both failure modes are silent: pip never runs against a
# line that isn't there, and the app just falls back to a cruder heuristic
# instead of erroring. Worth double-checking this file and env_setup still
# match any time a new dependency is added.)
# ============================================================

# Speaker diarization (Milestone 6 — see integration/whisper_transcriber.py
# _cluster_segments_by_voice()). Groups transcript segments by actual voice
# similarity instead of just silence gaps, so "Speaker_N" tracks the same
# person for the whole match. CPU-only, fully offline, no account/API key —
# a ~17MB PyTorch d-vector model (torch itself is the heavy part of this,
# tens/hundreds of MB — a real weight tradeoff on a "single portable .exe"
# app, worth checking the built USB size after adding this). If this or
# scikit-learn isn't installed, diarize_speakers() just falls back to the
# original silence-gap heuristic automatically — nothing else breaks.
resemblyzer>=0.1.4
scikit-learn>=1.3.0
# webrtcvad (pulled in by resemblyzer) drags in the ancient, Python-2-era

# worse, PyInstaller can bundle it and have it shadow the real stdlib
# typing module inside the frozen .exe. build_and_deploy.bat's :env_setup
# step runs `pip uninstall -y typing` unconditionally right after
# attempting to install the above -- whether that install succeeds or
# fails, so a failed attempt can never leave "typing" stranded in the
# build venv either (safe either way -- nothing here actually imports
# that package), so this no longer needs to be done by hand.
